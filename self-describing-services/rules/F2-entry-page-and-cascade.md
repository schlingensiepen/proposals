# F2 · Entry page and cascade: everything linked, decide first, load second

**Applies to:** builder.

**What holds.** The unauthenticated entry page (~20 lines at the base URL) suffices for the decision whether the service is needed — and it **lists and links every part of the description**: usage description, interface description, every part description (each with one sentence of purpose), and the anchor skill. The steps are linked to one another; only what is actually needed is loaded on, and only once the decision has been taken — all description steps are reachable without authorization (F4). How every text is cut and how the entry page links is stated in F20.

**Why.** The context window is the consumer's scarce good: an agent must be able to reject a service *before* he has read it in full. And the full linking is the hypertext strength that makes remembering minimal — anyone who knows one address reaches everything from there and knows at every link what is behind it.

**Considered and rejected.** *A single large description document* — forces a full-text load before the decision. *Fixed, standardized paths as a precondition* — recognizability is pleasant, but the entry page opens up the rest by reference; a path convention is a comfort, not a condition (deliberately left open; see "Not yet settled" in the scope).

**How you notice it is violated.** Agents regularly load the complete description and only afterwards discover that the service does not fit — or they find a part of the description only because somebody outside the service has linked to it.
