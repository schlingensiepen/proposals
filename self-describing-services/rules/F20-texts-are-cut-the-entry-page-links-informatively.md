# F20 · Texts are cut, the entry page links informatively

**Applies to:** builder (in a retrofit: façade operator).

**What holds.** Every delivered text of the description is cut so that at each step only what the next decision needs is loaded; the rest stays a link. The entry page links informatively: at every link it says what awaits the reader behind it, for every part description one sentence on what the part does. The sequence "short description, link, long description, link, …" is not a stylistic device but care for the context window.

**Why.** The context window is the consumer's scarce good: an agent must be able to reject a service *before* he has read it in full. An agent comes with a concern, not with an appetite for reading; and because the entry page says what lies behind every link, he knows permanently where the unread material lives. An unexplained structure, by contrast, forces him to grope around: then he loads everything after all.

**Obvious and rejected.** *A single large description document*: forces a full load before the decision. *Explaining everything in one piece*: punishes every consumer with the full load, even for the smallest question. *Links that do not say what lies behind them*: force groping around.

**How you notice it is violated.** Agents regularly load the complete description and only afterwards discover that the service does not fit, or they regularly load the full description for a simple query.
