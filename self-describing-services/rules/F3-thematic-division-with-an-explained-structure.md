# F3 · Thematic division with an explained structure

**Applies to:** builder.

**What holds.** The description SHOULD be broken down into thematic parts whose structure the entry page itself explains: at every link to a part it says what the part does. The builder chooses the axes according to the consumers' concerns — for instance core function vs. administration, data access vs. rights assignment, file handling as a group of its own, because not every use case involves files. The same division applies to the anchor skill package: one file per topic. Independently of the division, every text is cut and every link says what is behind it (F20).

**Why.** An agent comes with a concern, not with an appetite for reading: at the traffic service he loads "contribute" and leaves upload formats and POI administration unread — the context window stays free, and because the short version explains the structure, he knows permanently where the unread material lives. An unexplained structure, by contrast, forces him to search: then he loads everything after all.

**Considered and rejected.** *Explaining everything in one piece* — punishes every consumer with the full load, even for the smallest question. *Division by internal modules instead of by concerns* — the consumer thinks in "I want to learn/contribute something", not in the operator's module names.

**How you notice it is violated.** For a simple query, agents regularly load the full description — or the consumers' questions spread crosswise to the parts on offer, because the axes miss their concerns.
