# Terms

| English term | Explanation | Deutscher Begriff | Erläuterung |
|---|---|---|---|
| Interface description | the machine-readable description of the mechanics: operations, fields, types, error formats, examples; generated from the code and editorially enriched (with HTTP APIs typically OpenAPI). | Schnittstellenbeschreibung | die maschinenlesbare Beschreibung der Mechanik: Operationen, Felder, Typen, Fehlerformate, Beispiele; aus dem Code generiert und redaktionell angereichert (bei HTTP-APIs typisch OpenAPI). |
| Usage description | the prose document delivered by the service, carrying the overarching behavior: what the service is meant for, workflow, duties toward the user, handling of the secret. | Benutzungsbeschreibung | das vom Dienst ausgelieferte Prosa-Dokument mit dem übergreifenden Verhalten: wofür der Dienst gedacht ist, Arbeitsablauf, Pflichten gegenüber dem Anwender, Umgang mit dem Geheimnis. |
| Entry page | the unauthenticated short description (about 20 lines) at the base URL; it lists and links all remaining parts of the description together with their purpose. | Einstieg | die unauthentifizierte Kurzbeschreibung (~20 Zeilen) an der Basis-URL; verzeichnet und verlinkt alle übrigen Teile der Beschreibung samt deren Zweck. |
| Cascade | the staggering of entry page, usage description, interface description (including the part descriptions), ordered by loading cost: decide first, then load. | Kaskade | die Staffelung Einstieg → Benutzungsbeschreibung → Schnittstellenbeschreibung (samt Teil-Beschreibungen), geordnet nach Ladekosten: erst entscheiden, dann laden. |
| Part description | the thematic excerpt of the description for one delimited area of tasks (in the traffic service: learn, contribute, data-set upload, POI); loadable on its own, listed with its purpose on the entry page. | Teil-Beschreibung | der thematische Ausschnitt der Beschreibung für einen abgegrenzten Aufgabenbereich (beim Verkehrsdienst: erfahren · beitragen · Datensatz-Upload · POI); einzeln ladbar, am Einstieg mit Zweck verzeichnet. |
| Anchor skill | the storable skill provided by the service, containing nothing but purpose, target and links to the self-description: an empty shell that anchors triggering in the user's skill catalog. Not to be confused with the façade: the anchor skill forwards to the service, the façade describes a foreign API. | Anker-Skill | der vom Dienst bereitgestellte, speicherbare Skill, der nichts enthält als Zweck, Ziel und Links auf die Selbstbeschreibung: eine leere Hülse, die im Skill-Katalog des Anwenders das Auslösen verankert. Nicht zu verwechseln mit der Fassade. |
| Façade | a description service of one's own that delivers the cascade for a foreign existing API without touching its data traffic (retrofit). | Fassade | ein eigener Beschreibungsdienst, der die Kaskade für eine fremde Bestands-API ausliefert, ohne deren Datenverkehr zu berühren (Nachrüstung). |
| Tenant | a delimited area of use within a multi-tenant service (its own identifiers, its own rights, possibly its own hostname); discovery decisions can be taken per tenant. | Mandant | ein abgegrenzter Nutzungsbereich eines mehrmandantenfähigen Dienstes (eigene Kennungen, eigene Rechte, ggf. eigener Hostname); Discovery-Entscheidungen können je Mandant getroffen werden. |
| Instance | a concrete installation of a service, or of a piece of service software, under its own base URL; remembering, anchoring and granting rights happen per instance. | Instanz | eine konkrete Installation eines Dienstes bzw. einer Dienstsoftware unter eigener Basis-URL; gemerkt, verankert und mit Rechten versehen wird je Instanz. |
| Harness | the runtime environment in which an agent runs, together with its storage options: session memory, skill catalog, environment variables. It belongs to the user or his platform, not to the service. | Harness | die Laufzeitumgebung, in der ein Agent läuft, mitsamt ihren Ablagemöglichkeiten: Session-Gedächtnis, Skill-Katalog, Umgebungsvariablen. Er gehört dem Anwender bzw. seiner Plattform, nicht dem Dienst. |
| Secret | every confidential credential the consumer needs in order to make a call: API key, password, or a token. | Geheimnis | jedes vertrauliche Zugangsdatum, das der Konsument zum Aufruf braucht: API-Key, Passwort, oder ein Token. |
| Ranking | the fixed order of sources for a secret: environment (under a canonical name), pass-through file, last the once-only channel; imported from `where-a-secret-comes-from` (F13). | Rangfolge | die feste Reihenfolge der Bezugsquellen eines Geheimnisses: Umgebung (unter einem kanonischen Namen), Durchleitungs-Datei, zuletzt der Einmal-Kanal; importiert aus `where-a-secret-comes-from` (F13). |
| Once-only channel | the source used exactly once; for the consumer the context window: name it once, persist it immediately, never repeat it (F13). | Einmal-Kanal | die Quelle, die genau einmal benutzt wird; beim Konsumenten das Kontextfenster: einmal nennen, sofort persistieren, nie wiederholen (F13). |
| Capability | a single, narrowly delimited ability at a service (for instance: contributing reports); the token is the artifact that embodies exactly one of them (F12). | Capability | eine einzelne, eng abgegrenzte Fähigkeit an einem Dienst (etwa: Meldungen beitragen); das Token ist das Artefakt, das genau eine davon verkörpert (F12). |
| Token | the recommended access artifact for new builds: narrowly cut, one capability per token. Every token is a secret; not every secret is a token. | Token | das empfohlene Zugangsartefakt bei Neubauten: eng geschnitten, eine Fähigkeit pro Token. Jedes Token ist ein Geheimnis; nicht jedes Geheimnis ist ein Token. |
| Self-registration | the optional open method by which a consumer receives a token in exchange for a free-text self-introduction; in two flavors, automatic and by-request (F14). | Selbstregistrierung | die optionale offene Methode, über die ein Konsument gegen eine Freitext-Selbstvorstellung ein Token erhält; in zwei Geschmacksrichtungen, automatisch und beantragend (F14). |
| Display string | the short, pronounceable, non-secret handle to a token (8 lowercase characters) by which humans talk about tokens and grant rights without ever naming the secret (F14). | Display-String | der kurze, aussprechbare, nicht geheime Griff zu einem Token (8 Zeichen, Kleinbuchstaben), über den Menschen über Tokens sprechen und Rechte vergeben (F14). |
| Delivery form | media type, character set and headers with which a description document or an answer is delivered; part of the description: what the reader cannot accept, he has not received (F16). | Auslieferungsform | Medientyp, Zeichensatz und Kopfzeilen, mit denen ein Beschreibungsdokument oder eine Antwort ausgeliefert wird; Teil der Beschreibung (F16). |
| Weakest intended reader | the simplest fetch tool with which a consumer should still be able to use the service, as the builder intends; the yardstick for defaults (F16). | Schwächster vorgesehener Leser | das einfachste Abrufwerkzeug, mit dem ein Konsument den Dienst nach Absicht des Erbauers noch benutzen können soll; der Maßstab für Voreinstellungen (F16). |
| Mode of operation | the form in which a consumer deals with the service: reading prose or processing structures; a switch in mid-flow is announced, better avoided (F16). | Betriebsart | die Form, in der ein Konsument mit dem Dienst verkehrt: Prosa lesen oder Strukturen verarbeiten; ein Wechsel mitten im Ablauf ist anzukündigen, besser zu vermeiden (F16). |
| Present tense | the property of a description of saying exclusively what the service knows now: no hindsight, no removed forms, no decision history (F17). | Gegenwartsform | die Eigenschaft einer Beschreibung, ausschließlich zu sagen, was der Dienst jetzt kennt: keine Rückschau, keine entfallenen Formen, keine Entscheidungsgeschichte (F17). |
| Inside knowledge | knowledge only whoever builds or runs the service has: requirement identifiers, decision numbers, file names, internal module names, project jargon; unresolvable for the reader of a delivered description (F18). | Innensicht | Wissen, das nur hat, wer den Dienst baut oder betreibt: Anforderungskennungen, Entscheidungsnummern, Dateinamen, Namen interner Module, Projekt-Jargon; für den Leser unauflösbar (F18). |
| Closure | the property of a description that the reader can resolve everything it mentions or demands with the description itself and the answers of the service; every identifier to be substituted has a named call that yields it (F18). | Geschlossenheit | die Eigenschaft einer Beschreibung, dass der Leser alles, was sie erwähnt oder verlangt, mit ihr selbst und den Antworten des Dienstes auflösen kann; jede einzusetzende Kennung hat einen benannten Aufruf, der sie liefert (F18). |
| Check (gate) | an automatic check in the build of the service that makes the build fail when a rule is violated; the form in which this concept keeps intentions (F6, F17, F18, F22). | Prüfregel (Gate) | eine automatische Prüfung im Bau des Dienstes, die den Bau scheitern lässt, wenn eine Festlegung verletzt ist (F6, F17, F18, F22). |
| Principle and case | the division of a behavior rule: the *principle* stands exactly once in the usage description, the *case* at the operation it concerns; nothing is spelled out in both places (F22). | Prinzip und Fall | die Aufteilung einer Verhaltensregel: Das Prinzip steht genau einmal in der Benutzungsbeschreibung, der Fall an der Operation, die es betrifft; nichts steht an beiden Orten ausformuliert (F22). |
| Empty state | the state of a service that runs but is not set up yet; it lies between "does not exist" (404) and "here is the description" (F21). | Leerer Zustand | der Zustand eines Dienstes, der läuft, aber noch nicht eingerichtet ist; liegt zwischen „gibt es nicht" (404) und „hier ist die Beschreibung" (F21). |
| Setup | the step after which the service can carry out its function for a use case; in the reference implementation, the first mailbox set up. | Einrichtung | der Schritt, nach dem der Dienst seine Funktion für einen Anwendungsfall erfüllen kann; in der Referenzumsetzung das erste eingerichtete Postfach. |
| Setup page | the answer of the entry page in the empty state, with status 200: what the service is, that it is not set up yet, what would have to be done next (F21). | Einrichtungsseite | die Antwort des Einstiegs im leeren Zustand mit Status 200: was der Dienst ist, dass er noch nicht eingerichtet ist, was als Nächstes zu tun wäre (F21). |
| Onboarding from the URL | connecting a service by giving an agent nothing but its address. | Onboarding per URL | einen Dienst anbinden, indem man einem Agenten nur seine Adresse gibt. |
| Service fingerprinting | anonymous reconnaissance of which software runs where. | Service-Fingerprinting | anonyme Erkundung, welche Software wo läuft. |
| Operating parameter | a setting made by the operator that governs the behavior of the running instance; here, whether the cascade answers in the empty state. | Betriebsparameter | eine Einstellung des Betreibers, die das Verhalten der laufenden Instanz bestimmt; hier, ob die Kaskade im leeren Zustand antwortet. |
| Builder | whoever builds the service and its description. | Erbauer | wer den Dienst und seine Beschreibung baut. |
| Façade operator | whoever retrofits a foreign API with a façade (retrofitter). | Fassaden-Betreiber | wer eine fremde API mit einer Fassade nachrüstet (Nachrüster). |
| Operator | whoever runs the service. | Betreiber | wer den Dienst betreibt. |
| Consumer | whoever calls the service, usually an agent. | Konsument | wer den Dienst aufruft, meist ein Agent. |
| User | the human for whom the consuming agent works. | Anwender | der Mensch, für den der konsumierende Agent arbeitet. |
| Rule | an entry with one answer; giving it up means no longer using the concept. | Festlegung | ein Eintrag mit einer Antwort; wer sie aufgibt, benutzt das Konzept nicht. |
| Choice | an entry where the concept does not decide but names options with consequences; the adopter decides and records. | Wahlpunkt | eine Stelle, an der das Konzept nicht entscheidet, sondern Optionen mit Folgen nennt; der Übernehmende entscheidet und hält fest. |
