# F12 · Delivery duty: the code travels with the service

**Applies to:** Operator (for the benefit of the agent).

**What holds.** Every rule of this concept that addresses agents — the storage order (F6), the binding (F7), the never-rules (F10), the way of speaking (F11) — MUST be in the documentation or the self-description of the service itself, in the service's own words.

**Why.** The consuming agent does not know this concept; it knows only what its service and its user tell it. An agent rule that is only here reaches nobody — it would be hope, not a rule. The chain reads: concept → operator → service documentation → agent; only the delivery turns recommendations into effective duties.

**Considered and rejected.** *Teaching the rules to every agent platform individually* — the N×M problem, this time for behavioral rules. *Relying on general platform ground rules* — they vary; what the service needs, the service has to say.

**How you notice it is violated.** Agents of different platforms handle the same token differently — some persist it correctly, others quote it in the chat — although all of them have read the same service documentation.
