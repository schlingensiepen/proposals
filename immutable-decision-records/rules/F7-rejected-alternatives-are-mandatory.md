# F7 · The rejected alternatives are mandatory, with their reasons

**Applies to:** author; readers treat them as binding context.

**What holds.** Every record names the options that were seriously on the table and says, for each, why it did not win.

**Why.** Without this part, the next person proposes the rejected solution again, and nobody remembers the reason, so it is recomputed or, worse, adopted. The value of a set of decision records is not in the decisions that were taken; those show up in the result anyway. It is in the ones that were **not** taken. This holds all the more when assistant systems read along: they reliably propose the most obvious solution, and the most obvious one is often exactly the one that was once rejected for good reason.

**Considered and rejected.** *Record only the chosen option and keep alternatives in memory*: memory is the least reliable part of the system and the only part nobody backs up. *List alternatives without reasons*: a list without reasons is an open invitation to evaluate them all over again.

**How you notice it is violated.** In a meeting someone proposes what the set of records already rejected once, and nobody notices.
