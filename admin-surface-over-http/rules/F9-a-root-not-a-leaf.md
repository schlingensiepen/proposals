# F9 · The administration secret is a root, not a leaf, and whoever introduces a root owes revocation, change, lifetime and the case of loss

**Applies to:** builder · operator.

**What holds.** The administration secret is **not a narrow access** among others: it cannot perform any function itself, but in one step it can issue an access that can, and withdraw any existing one. It is the **root** of the rights hierarchy, not a leaf in it; and the base cut gets by without administrative rights precisely because it has no moment at which somebody gives an access something. Whoever builds the surface introduces that moment again and owes four answers. **Revocation:** the administration secret can be replaced at any time and without precondition (remove the variable or set it to the agreed value, restart, take the new secret from the log), and an operation that takes rights away is never harder to reach than the one that gives them: every issued access stays narrowly cut and individually revocable, over both pass-throughs. **Change:** see F8, two moves, upper and lower rank. **Lifetime:** it does not expire by itself; it lives in the process definition or in its file for as long as the operator leaves it there, and the service makes the age of issued accesses visible (last use per account) instead of limiting it. **Loss:** there is no re-display; a lost administration secret is replaced, not looked up. And two operating rules follow that would otherwise look overcautious: the secret is treated like an administrative password, not like an API key (it never goes into an address, never onto a surface for weak callers, never into a transcript), and the administration address is kept as tight at the proxy as the environment allows (F4).

**Why.** The base cut has no permission model because configuration and access arise in one act and nobody ever adds anything to an existing access. An administration surface on the network makes exactly that act possible from afar, with a secret that entitles to it, and with that there is again something that can do more than the one function. That is the symptom by which the base concept recognizes the violation of its rule, and here it occurs knowingly. Whoever introduces it cannot argue it away, only limit it: the damage stays small because every issued access still unlocks exactly one variant and can be revoked at any time, because a rotated access is noticed at once when the legitimate holder is refused, and because the root itself is replaced with one restart. A time-limited window that is open only during a delivery and closes by itself afterwards would be the safer design; but it presupposes a delivery that can create something on the host system, and exactly that is missing here; opening a window by a restart would be an operational intervention for a routine task, and a security measure that turns a routine task into an intervention gets switched off or left open permanently. Expiry is dropped because the secret may stand in a deployment file and is meant to stay there; an expiry would lock out the operator without a shell without anybody having done anything. The price of this answer must be named honestly: between compromise and detection an access can be issued that works until it is withdrawn.

**Obvious and rejected.** *Treating the administration secret as one more capability token*: it embodies no capability but the granting of capabilities; whoever treats it so puts it onto a surface for weak callers or into an address and then has the root in the access log. *A time-limited issuing window*: the better design where a delivery with a channel inward can open it; not buildable here. *Automatic expiry*: locks out the operator without a shell. *Roles instead of one root ("may only read", "may only issue")*: the permission model the cut saves; without an object for a service with one function and one operator. *A re-display "for emergencies"*: every re-display is a query surface for whoever is already inside.

**How you notice it is violated.** Shutting down an access takes more than issuing it; or there is no way without a shell to replace the administration secret; or the administration secret stands in an address, on a surface for weak callers or in a transcript; or somebody treats it like an API key and leaves it in a script three people read.
