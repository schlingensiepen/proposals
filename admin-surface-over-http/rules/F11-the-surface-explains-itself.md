# F11 · The surface explains itself to the one who has nothing else

**Applies to:** builder.

**What holds.** The operator without a shell meets this port and has **nothing else**: no manual page, no command, no help option. The port therefore owes him four things, unconditionally and without any other concept: **(1)** an **entry page** at its base URL, readable without a secret and containing none, that says what this port administers, that it is **not** the user-facing surface, what one needs (the administration secret and where it comes from: variable, file, log) and what this port cannot do (perform the function, show secrets, change what exists); **(2)** **refusals** that name a way **this** surface has, not a command he does not have, not a header or a call of the user-facing surface; **(3)** wherever a **format statement about the secret** is made, one that describes **every valid** secret and not only the generated one, and wherever an example is shown, a visible placeholder; **(4)** a **readiness point** that says only "running" without a secret. There is **no** anchor package to store here: the administration is not addressed to agents that trigger on their own. And because two surfaces are two pass-throughs onto the same operations (F2) and their properties are held structurally (F3): **if you have a check rule for one surface, you use it for the second, not a copy of it.** This proposal orders nothing more for the description of the surface. Anyone who also applies the concept of self-describing services owes this surface more than this core; but that follows from that concept, not from this one; the concept and the sources say how the two come together.

**Why.** Everything here follows from the situation, not from a concept. Two ports under two names of the same software look alike to a caller, and an access sent to the wrong one produces no error one understands; so the entry page says which port this is. The operator without a shell cannot fall back on any command; so no refusal may recommend one to him. The format statement has its own incident on this surface: it named the prefix of generated secrets as the form of all, and the author's valid secret, set through the variable, had none; a caller that had checked the statement would have refused it. The readiness point is needed by the platform that supervises the container before anybody has a secret. And the rule about the check rule is F2 applied to the checks themselves: two versions of a check are two implementations of the same judgment, and they drift apart as soon as someone touches only one. The check of the author's user-facing surface got six new assertions after a review, the hand-copied version for the administration did not, and there a description passed that kept advertising removed behavior. That this proposal demands no more (no description cascade, no enriched contract, no external review) is not a waiver but a matter of responsibility: the base this proposal builds on knows no self-description, and a proposal lays down what follows from its own question. The first version of this rule did more and thereby governed into a neighboring concept.

**Considered and rejected.** *Demanding the full self-description unconditionally*: prescribes cascade, contract, gate and external review to everyone who builds an administration surface, although the base of this proposal knows none of it; exactly the mistake of the first version. *Demanding it conditionally ("if you apply that concept, then …")*: still this proposal making laws about the other; two concepts are combined, neither stretches into the other. *Demanding nothing ("the operator knows what he started")*: he has the port and nothing else, and he does not know which of two it is. *Describing the administration along with it in an open description of the user-facing surface*: then it is in a document anybody reads (F4). *A hand-written operating manual in the repository instead of an entry page at the port*: the operator without a shell does not have the repository in front of him, but the port. *An anchor package here too, "for completeness"*: there is nobody who is to trigger the administration on being told "store this". *Copying the check rule of one surface for the other*: the copied version is the one in which the next assertion is missing.

**How you notice it is violated.** An operator asks which of two ports is which; or a refusal of the administration surface recommends a command or a header of the user-facing surface; or a format statement refuses a valid secret; or the same check exists twice and one version lags behind.
