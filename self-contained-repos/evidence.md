# Evidence

> This evidence describes the series as it stood when version 0.9 was written, a few weeks after the series began. It is evidence of the construction, not of operation over a longer period.

## In operation: the proposal series of the author

The procedure is applied in the repository in which this proposal itself lives. Implemented there are: an entry point that branches to two tasks, creating or maintaining a proposal, and finding and using a proposal, with an instruction of its own for each task; an explicit linking rule under which references stand exclusively in the sources; the inlining rule for decisions; the check rule "does it work with dead links?" as a section of the root entry point; self-contained agent instructions per proposal, in which numbers of the discussion paper appear only as provenance notes; and a signpost for a second widespread agent tool that points exclusively to the one entry point.

## An unplanned test from practice

In a test run, a context-free agent was to build a tool from a single proposal alone. Among other things it reported that the proposal referred, for one rule, to a sister document it did not have; it was "strictly speaking not fully self-contained". That is exactly the check rule of F1, applied by somebody who did not know it. The passage was written out; a second test run with a fresh agent confirmed explicitly that no prerequisite for understanding points outside any more. This is currently the strongest evidence for the concept.

## Origin of the inlining rule and of F4

The inlining rule arose as an explicit decision of the author against a template that provided only provenance links for decisions. The reasoning at the time: a document that points to a decision log for its rules cannot be followed without that log, so both belong in it. F4 likewise arose from an objection to a checklist that hung its points on numbers of the main document: "Then the separate file is pointless."
