# F2 · An entry point that branches instead of explaining

**Applies to:** writer.

**What holds.** There is exactly one file that an arriving person reads first. It does not explain the undertaking but names the two or three actual tasks that arise on this repository, and points per task to the instruction that belongs to it. It is short enough to be read before the work, and it stands at the place where the widespread agent tools look first; where several such places are customary, the others point only to this one.

**Why.** An arriving person comes with an intention, not with an appetite for reading, just like an agent with an assignment. An entry point that explains gets skimmed; one that branches gets used. The limit of two or three tasks is not a formality: whoever lists more has usually stopped naming tasks and started naming topics, and the arriving person again does not know where they belong.

**Obvious and rejected.** *The user manual as entry point*: it addresses users of the product, not contributors to the repository; serving both intentions in one document means serving neither of them well. *Several equal entry files for different tools*: they drift apart; one leads, the others point to it. *No entry point, but telling directory names instead*: works for whoever already knows the convention, that is, for nobody who is new.

**How you notice it is violated.** A newcomer asks "where do I start?"; or two entry files say different things.
