# F3 · One task definition per recurring activity

**Applies to:** writer.

**What holds.** For every activity that recurs on the repository there is an instruction of its own: what is to be done, in which order, and how one recognizes that it is finished. It describes the activity completely: not the undertaking, not the tool, not the motivation.

**Why.** Recurring activities are the place where experience otherwise gets stuck: everyone does it a little differently, and anyone new does it wrong without anybody noticing. Written down, they become something an agent can carry out unchanged, and a checklist against which a human checks themselves.

**Considered and rejected.** *Everything in one big contributor guide*: it grows long, and anyone who carries out a task first has to dig out their part; the entry point (F2) does exactly that better. *Describing the activity in the ticket*: holds for this one time and is gone the next time. *Pointing to general conventions*: everyone knows them differently.

**How you notice it is violated.** The same activity is carried out differently by two people, and both consider themselves right.
