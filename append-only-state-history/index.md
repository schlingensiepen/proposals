# Rules

One answer each; give one up and you are no longer using the concept. F1 to F4 were developed on a flat model; how they carry over to object trees is not yet settled (see the scope).

* [F1 Every change creates a state](./rules/F1-every-change-creates-a-state.md) - No operation changes an existing state; everything, even a report that something is lost, creates a new one.
* [F2 Attachments are carried over, not copied](./rules/F2-attachments-are-carried-over-not-copied.md) - A new state points to the attachments of its predecessor that still apply; no second file is created.
* [F3 Exactly one living metadata entry, and only on the latest state](./rules/F3-exactly-one-living-metadata-entry.md) - One machine-added entry may arise and change on the latest state only, and freezes when the next state follows.
* [F4 Creator and origin are snapshots, not references](./rules/F4-creator-and-origin-are-snapshots.md) - Who created a state and from where is recorded in it as text, not as a reference to a user record.
